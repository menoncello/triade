# Story 1.6: Input por swipe RNGH + edge-cases contract

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a player,
I want reliable swipe input that never loses a move,
so that my swipes always resolve predictably, even under interruptions.

## Acceptance Criteria

1. **Given** the game board active,
   **When** the player swipes,
   **Then** the move resolves via RNGH `Gesture.Pan()` with a ~10px activation threshold, and direction maps to the engine `move()` (UX-DR-3).
2. **And** a cancelled gesture / system interruption causes no move, no spawn, no turn consumed — the board stays as it was.
3. **And** releasing off the board mid-gesture resolves the swipe as captured (the gesture owns the move).
4. **And** a concurrent second finger must not dispatch a second `move()` while a swipe or its animation is in flight (the in-flight gate — first-finger-wins is a manual device-validation item; the native RNGH default tracks extra pointers, D1, so it is not enforced in code).
5. **And** a swipe during an in-flight animation is rejected (never queued) while the input gate is closed — the first ~30% of the move animation (~78ms) — and accepted once the gate opens, where the board re-plans and tiles retarget forward to their committed targets (early-input release, UX decision 2026-08-18); no board mutation ever happens while the gate is closed.
6. **And** the pause button is always reachable during a match (top-right), letting the in-flight swipe settle before freezing (UX-DR-11).

While an animation is in flight (a move was dispatched but the tiles have not settled), further swipes are **rejected silently** — no `move()`, no spawn, no turn consumed, board unchanged, no punish animation. **Mechanism (recommended):** add an `onMoveSettled?: () => void` prop to `GameBoard` (`triade/src/render/GameBoard.tsx`) fired via `runOnJS` after the slide/merge/spawn animation settles (mirror the existing `onVanish` pattern at `GameBoard.tsx:103-112`), and keep a `busyRef` in `App` that is set when `doMove` dispatches **an effective move** and cleared in `onMoveSettled`; the gesture ignores swipes while `busyRef` is set. **Set `busyRef` ONLY when `result.moved === true`** — a noop (`moved:false`) produces an empty `transitionPlan`, so **no animation runs and `onMoveSettled` never fires**; setting `busyRef` on dispatch unconditionally would deadlock the board on the first noop swipe. The noop path must leave `busyRef` untouched and simply return. Alternative acceptable mechanism: an App-level busy ref timed to the animation duration — but prefer the GameBoard callback so the gate matches the real settle. **Architecture lean: REJECT, not queue** (the architecture's general event rule is "no message queue").

The `onMoveSettled` callback must fire once, after the last of these completes. Recommended approach: count active settle-tracked tiles for the move and decrement per tile in the `withSpring`/`withTiming` completion callbacks, invoking `onMoveSettled` when the count reaches zero — and in each callback, ignore `finished:false` (a spring/timing interrupted by a re-target does NOT count as settled; the re-target's own callback will eventually fire). Keep the plan in a ref so the count can be derived without stale-closure reads. The timed fallback (busyRef cleared after max animation duration) avoids this aggregation entirely but is less faithful to the real settle.

- **RNGH API is v2 (`onEnd(event, success)`).** Expo SDK 57's bundled version matrix resolves `react-native-gesture-handler ~2.32.0` (confirmed in `expo/bundledNativeModules.json`), which is the v2 API this story's T3.3/T3.4 use: `onEnd(event, success)` receives a `success: boolean` (`false` = cancelled/system interruption). RNGH v3 (not yet on SDK 57) renames the callback to `onDeactivate`/`onFinalize` and inverts the flag to `event.canceled`. Do not "modernize" the callback unless the installed version is actually v3 — T3.4.2 covers the check.
- **This story closes the temp-harness debt.** The deferred-work ledger records three entries this story owns: the harness + ScrollView shipping to production, the stale-board-closure that drops rapid same-frame moves, and the preview/hint overlap. T3.1 removes all of them. The FPS-baseline/score debug text may stay (dev aid) but the `DirButton` controls and the hint must go.
- **The engine has NO `ok | rejected` union.** The ported engine returns a single `MoveResult` discriminated by `moved: boolean` (`src/engine/core/game.ts:32`). `moved:false` IS the rejection signal: noop results keep the board, score 0, no spawn (`game.test.ts:319-328`), and `transitionPlan` returns `[]` so nothing animates. Do **not** refactor the engine into an `ok|rejected` union — the story's "per the engine `ok | rejected` contract" maps to `moved`; the real missing piece is the **visual in-flight gate** (GameBoard gives no settle signal today — animations are fire-and-forget springs).
- **Swipe-during-animation today is technically safe but visually wrong.** Because `App` commits `board` immediately and `GameBoard` diffs committed boards (`prevBoardRef`, `GameBoard.tsx:216-224`), a mid-flight swipe would re-derive a new plan and retarget still-animating tiles instead of queueing/rejecting. It won't crash, but it violates AC-4/AC-5. The gate is mandatory.
- **Pause must remain reachable** (AC-6, UX-DR-6/UX-DR-11). The gesture wraps only the board container; the `Hud` overlay (`zIndex: 1`) sits above it with `pointerEvents="box-none"` so touches pass through except on the pause button. The actual pause overlay/state is Epic 6 — this story only guarantees the button stays tappable and outside the swipe rect.
- **The PWA stays frozen.** `js/game.js`, `js/ui.js`, `js/debug.js`, `test/game.test.js` — READ-ONLY. No parity mandate with the RN app (`NFR-9`). The web app's `setPointerCapture` swipe is legacy and not binding.
- **No engine rule changes.** This story touches `src/ui` (new pure module + App wiring) and `src/render/GameBoard.tsx` (optional settle callback). `src/engine/core` stays untouched — any rule change requires its own tests + trace preservation.
