# Accessibility Review — Tríade (3-clone)

## Verdict

The pair establishes a genuinely strong, honest accessibility floor: contrast prose recomputes true against the hexes, the 44×44pt floor is enforced at component level, Reduced Motion is stated consistently with the GDD/architecture (in the behavioral spine), the fixed-numeral/dynamic-type split is defensible and flagged in both files, and the three free themes + shape/text-beyond-color are locked. The load-bearing weakness is **S9.2**: it is one sentence whose central claim — "No labels invented in UI," labels from the per-tile trace — is not literally implementable, and it leaves the *entire VoiceOver model* (how a VoiceOver user swipes, what is announced for merges/noops/score, chrome labels) to be invented by E9 story-dev. Medium gaps: the Reduced Motion gated set omits flash/particles and overshoot-and-snap, the tone screen's ~2s auto-advance contradicts "no time pressure anywhere" and can race the reader, and the leaderboard tab is the one interactive component with no size floor.

## Findings

- **[high]** **The screen-reader input model is unspecified, and a swipe-primary game + VoiceOver is the hard problem S9.2 leaves unsolved.** *Location:* EXPERIENCE.md:94–95, 104, 123 (swipe ~20px threshold / tap primitives; "screen reader announces tile value + position"; "touch swipe (primary)"). iOS VoiceOver intercepts single-finger swipes for navigation, so the primary move gesture has no defined path for a VoiceOver user. The spine never says whether E9 builds 3-finger-swipe moves, a rotor action, "direct manipulation" passthrough, or gesture alternates. *What E9 must build:* a VoiceOver-specific gesture contract, per-tile `accessibilityElement`s (Skia tiles are not RN views — labels must be exposed via a bridge, which the spine doesn't mention), and focus management as tiles move. *Fix:* add a "Screen Reader Contract" subsection naming the interaction scheme and the Skia-to-`UIAccessibility` label exposure.

- **[high]** **"No labels invented in UI" (from the per-tile trace) is not implementable as written — trace lacks score, game-over, resting tiles, preview, and all chrome.** *Location:* EXPERIENCE.md:104. The per-tile trace (`{ value, to:[r,c], from:[[r,c]...], spawned }` — project-context.md:38, game-architecture.md:250–257) covers only tiles that moved/merged/spawned in a move. It cannot source: the resting 16-tile board readout (initial 9 tiles have no trace), score changes (separate `score` field), game-over state (separate event), the preview card value (N3 pending spawn), or any menu/overlay control. Read literally, the rule forbids authored labels for Resume/Restart/Quit, theme names, leaderboard rank/score/date, banners — which are un-derivable and must be i18n strings. *What E9 must build:* a scoped rule — board labels from engine board-state + move events (not trace alone); chrome labels from i18n keys. *Fix:* re-scope the sentence: "board labels are engine-derived (board grid + per-move events); chrome labels are i18n-authored — never ad-hoc strings in UI."

- **[high]** **No announcement content contract: merges, noop swipes, score noise, game-over copy, new-record, preview, and Iniciante banners are all undefined.** *Location:* EXPERIENCE.md:104 (the only a11y sentence), 80 (noop = "silent control flow"), 83 (new record = visual accent only), 65 (preview card), 70 (banners), 69 (reward prompt). *What E9 must build:* exact announcement strings/order (e.g. "tile 12, row 3, column 2"), merge announcements (derivable from trace `from` length, but nothing says to announce), a noop acknowledgment (a screen-reader user on a rejected move gets zero feedback — "silent control flow" is a11y-invisible), a score-announce throttle (every-swipe announcements are unreadable; announce-on-merge vs quiet), game-over + new-record text, preview-card announcement, and banner/reward-prompt announcements. *Fix:* a small announcement table (event → what VoiceOver says → source) in the Accessibility Floor.

- **[medium]** **Reduced Motion's gated set is incomplete in the spines vs the architecture: flash/particles and overshoot-and-snap are omitted, and DESIGN.md never mentions Reduced Motion at all.** *Location:* EXPERIENCE.md:106, 139 ("disables/smooths shake and bullet time"); architecture game-architecture.md:660 ("cuts flash/slow-mo"); EXPERIENCE.md:134 (overshoot/snap, color flash + particles); DESIGN.md:241 (feel layer), 262 (glow on 1536+). A consumer reading only the spines would keep flash/particles, the overshoot scale animation, and the game-over soft fade (EXPERIENCE.md:82) under Reduced Motion, contradicting the architecture's reduced preset. A visual-only consumer of DESIGN.md sees glow and the feel layer as unconditional. *Fix:* enumerate the full gated set (shake, bullet time, flash/particles, overshoot scale, glow, fade) in both spines and add a Reduced Motion cross-reference to DESIGN Elevation & Depth / Feel layer. (Consistency win: both EXPERIENCE lines and the GDD say "keeps haptics and sound" and "sanctioned 60 FPS fallback" — that part is airtight.)

- **[medium]** **The tone screen's ~2s auto-advance contradicts "no time pressure anywhere" and can race the screen reader.** *Location:* EXPERIENCE.md:27, 78, 166 (tone ~2s, "ends on its own"), EXPERIENCE.md:109 ("No time pressure anywhere"). A ~2s timed auto-advance over a surface with content is a timing-race for VoiceOver users (the "controle sobre o caos" line can be cut off mid-announcement) and is the single timed surface in an otherwise timer-free game. *Fix:* state that the auto-advance pauses while a screen-reader announcement is in flight (or while VoiceOver is active), or explicitly declare the tone screen non-informational and justify the exemption.

- **[medium]** **The leaderboard tab is the one interactive component with no size floor, and its active-state text color is unspecified.** *Location:* DESIGN.md:105–109 (`leaderboard-tab`: no minHeight/minWidth, "compact segmented form"); EXPERIENCE.md:67 (interactive toggle). The 44pt floor is otherwise airtight — button/menu-item/pause-button/lane-card/leaderboard-row/settings-row are all 48pt (DESIGN.md:76–117), and the tile/preview are non-interactive. But "compact" tabs risk sub-44pt tap areas, and `activeFill: accent` has no stated text token (muted text on accent measures 1.26:1 — a failure if that's the pairing). Also unstated: prompt-banner dismiss target and tone-screen skip (implied whole-screen, EXPERIENCE.md:27) sizes. *Fix:* give `leaderboard-tab` an explicit ≥44×44 hit area and an active-tab text token (dark ink on accent), and state the banner-dismiss target.

- **[low]** **Contrast prose is honest but misidentifies the weakest pair; all other claims recompute true.** *Location:* DESIGN.md:207. Recomputing from the hexes: text on surface 13.06:1 (claimed 13.1), muted 5.56 (5.6), accent on surface 7.02 (7.0), accent on surface-raised 6.22 (6.2) — all accurate. Tile ink: every tier clears ≥4.5:1, but the *weakest* pair is `384` esmeralda profunda at **4.65:1**, not `24` cobre at 4.91:1 (the doc's "weakest pair is 24" is backwards; it says "384 clears as well," which is true but misranked). Both clear the 13pt 4.5 bar, and all clear the 3:1 large-text bar for 32pt numerals. Unclaimed combos in active use all pass on recompute: muted on surface-raised 4.92:1, accent record value on board 7.83:1, Jogar dark-ink label on accent 8.55:1. *Fix:* one-line correction naming 384 (4.65) as the weakest, 24 (4.91) next.

- **[low]** **Fixed tile numerals are defensible and stated consistently in both spines; the Skia rendering and 9pt floor deserve one explicit guard.** *Location:* DESIGN.md:213 (Skia-rendered numerals, bundled font), 223 ("tile numerals are fixed"); EXPERIENCE.md:108, 156. Consistent across both files and the decision is well-reasoned (in-tile legibility). But 6+ digit numerals at 9pt (`{typography.tile-6digit}`) render outside React/`UIFontMetrics`, so Dynamic Type can never enlarge them — that's the deliberate trade, yet the spine never states a *minimum* legible size or that the fixed numerals must stay readable at max Dynamic Type. Also the preview-card ink size is untyped (DESIGN.md:263). *Fix:* one line — "fixed tile numerals are a deliberate, flagged exception to Dynamic Type; they must remain legible at the largest accessibility text setting," and give the preview ink a size token.
