# 3-clone - Source Tree Analysis

**Date:** 2026-08-06

## Overview

Small, flat, dependency-free project. A single web part lives directly in the project root (no `src/` split): the app shell at the root, scripts under `js/`, styles under `css/`, tests under `test/`, tooling under `scripts/`, and generated icons under `icons/`. There is no build step and no `package.json`.

## Critical Directories

### `js/`

Game scripts, loaded by `index.html` in order `game.js → debug.js → ui.js`.

**Purpose:** All runtime JavaScript.
**Contains:** `game.js` (rules), `ui.js` (presentation/input), `debug.js` (dev tooling).
**Entry Points:** `game.js` UMD root export; `ui.js` self-invoking IIFE that bootstraps on load.

### `css/`

**Purpose:** All styling.
**Contains:** `style.css` with CSS custom properties for theming, tile color tiers per value, slide/spawn/merge animations, responsive board sizing via `min(90vw, 60vh, 520px)`, game-over overlay, and debug panel styles.

### `test/`

**Purpose:** Unit tests for the rules engine.
**Contains:** `game.test.js` — 26 tests covering the I/O matrix (merge rules, one-cell movement, spawn-after-effective-move, noop swipes, game-over detection) plus trace-level assertions.

### `icons/`

**Purpose:** PWA icons (self-generated, no external assets).
**Contains:** PNG icons at 180/192/512 px generated by `scripts/make-icons.js`.

### `scripts/`

**Purpose:** Build tooling.
**Contains:** `make-icons.js` — dependency-free Node script using `zlib` to generate PNG icons with a pixel-font "3" glyph and 3x3 supersampling antialiasing.

### `_bmad-output/`

**Purpose:** BMad Method workflow artifacts.
**Contains:** `implementation-artifacts/` (spec + deferred work ledger), `planning-artifacts/`, `test-artifacts/`.

## Entry Points

- **Main Entry:** `index.html` — the only HTML page; the app shell.
- **Script entry points:**
  - `js/game.js` — UMD module; `window.ThreeGame` in browser, `module.exports` in Node.
  - `js/ui.js` — IIFE that builds the board, binds input, and starts a new game on load.
  - `js/debug.js` — IIFE exposing `window.ThreeDebug`.
  - `sw.js` — service worker lifecycle (`install`/`activate`/`fetch`).
- **Tool entry points:**
  - `scripts/make-icons.js` — run `node scripts/make-icons.js`.
  - `test/game.test.js` — run `node --test`.

## File Organization Patterns

- One responsibility per file, flat layout (no deep nesting).
- Browser scripts are IIFEs that attach to `window` globals (`ThreeGame`, `ThreeDebug`); `game.js` uses a UMD wrapper so the same file works in Node for testing.
- No module system, no bundler — dependency order is maintained manually in `index.html`.
- Style class names follow a flat, descriptive convention (`tile-3`, `tile-big`, `tile-spawn`, `tile-merge`, `dbg-*`).

## Notes for Development

- **Keep it dependency-free**: the whole point of this project is zero runtime deps, no build step. Adding npm packages or a bundler violates the design intent (see spec boundaries).
- **Rules live only in `js/game.js`**: never duplicate merge/spawn/game-over logic in `ui.js`.
- **Testing requires the UMD export**: keep `game.js`'s Node compatibility intact so `node --test` keeps working.
- **Service worker cache name**: `CACHE_NAME = 'three-v4'`; bump it when the app shell changes to force re-caching.
- **Deferred work**: two accessibility items remain (pinch-zoom disabled via viewport meta; board `role="grid"` lacks row/gridcell semantics + live-region score announcements) — tracked in `_bmad-output/implementation-artifacts/deferred-work.md`.
