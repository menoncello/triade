## Part 1 — Epic Review

### 1.1 Delivery Summary

- **Stories delivered:** 1-1 (spike) · 1-2 (engine parity) · 1-3 (Skia board) · 1-4 (offline/persistence) · 1-5 (layout) · 1-6 (swipe input) · 1-7 (numeral legibility)
- **Test suite:** 186 triade tests + 26 frozen web PWA tests; `tsc --noEmit` clean.
- **Stack proven:** React Native (Expo SDK 57) + Skia renders 100% from an engine trace; MMKV chosen over AsyncStorage; offline/installable on iOS.
- **Web PWA (`js/game.js` et al.) left frozen and unmodified** throughout — enforced by every story's READ-ONLY rule. Faithful port, not a rewrite.

### 1.2 What Went Well

- **Pure-TS-frame-math + thin-RN-view split (ADR-01/05) worked.** Established in 1.1 and reused verbatim in 1.2–1.7. Every pure module is host-testable under `node --test`; the RN/Skia component is a thin binding. This is the single biggest win and the load-bearing pattern for the whole project.
- **The trace as the render contract.** `move()` returns `{ board, score, moved, trace }`; the Skia board renders 100% from the trace. Reused by 1.5/1.6/1.7. Set Epic 2 up well (the trace already carries `spawned`).
- **Determinism backbone locked in early.** `mulberry32` shared util + injectable `rng` param. Every parity/benchmark test depends on it.
- **CI gates shipped as code.** Purity/tripwire test that fails the build if a pure module imports RN/Expo or a HUD re-derives layout math — this is now the enforcement mechanism for the architecture invariants.
- **1-2 was cheap and high-value.** Verification + score state, not new engine code; only 2 test bugs. The spike (1.1) had already done the real port.
- **Benchmark gate shipped in the spike PR** and kept the cost-per-turn budget honest (even if the metric label needed correction — see debt).

### 1.3 What Didn't Go Well (systems, not individuals)

- **Recurring purity-scan escape pattern.** The pure-module scan is hand-maintained (`PURE_MODULES` list / `PURITY_FILES`). Every new pure file silently escaped the ADR-01/05 tripwire until manually added: 1-3, 1-5, 1-6, 1-7 all carried a patch for exactly this. A maintenance trap that will bite Epic 2's `spawnConfig`/`ceilingDetector`/`potResolver`/`weightedPicker` if not fixed.
- **Completion-note test counts drifted in every story.** 1-1 through 1-7 each had a review patch correcting a wrong test total in the story doc. The completion-note count is an unreliable artifact — a known QA gap.
- **Native/visual behavior is never automated.** Every story's on-device frame rate, landscape rotation, gesture interaction, and numeral legibility are deferred to manual simulator/device checks (TCC blocks assistive access; no physical iPhone). The 60 FPS / p99 < 16.7 ms budget remains unclosed evidence.
- **"Dev ships, review catches contract regressions."** High review churn across the epic (1-4 had 2 reviews / 16 patches; 1-6 had 2 calibration runs + re-review). The dev pass tends to ship correctness/contract regressions that the review pass catches — a process signal, not a person problem.
- **Post-review calibration arrived late.** 1-6 re-calibrated `SWIPE_THRESHOLD` 20→10px and switched to a timer-based early-input gate *after* the initial dev pass, because device playtest feedback came late. The threshold had felt "dead" vs the web PWA.

### 1.4 Breakthrough Moments (precedent for later work)

1. Pure-module + purity-scan pattern (reuse in Epic 2's spawn config).
2. Trace-as-render-contract (Epic 2's bigger spawns need no render rewrite).
3. `mulberry32` + injectable RNG (determinism backbone).
4. Purity/tripwire CI gate.
5. `runOnJS` fix for worklet→UI state updates (precedent for all Reanimated wiring).
6. In-flight input gate (REJECT not queue) — reusable for Epic 5 tutorial gestures.

### 1.5 Technical Debt Incurred

**High**
- **Device gate T5.2 (on-device p99 < 16.7 ms) still OPEN.** 60 FPS evidence is simulator-only (Mac GPU). AC-4 (1-1) and AC-5 (1-3) unmet on device. *Close before any store-submission claim.*
- **Architecture-vs-engine contract drift.** Architecture doc states `move()` returns `{ ok; state; events } | { ok: false; reason }` and "engine never throws" (NFR12). Shipped engine returns `{ board, score, moved, trace }` with `moved: boolean`; 1-6 Dev Notes explicitly warn "The engine has NO `ok | rejected` union — Do not refactor." **Epic 2/3 will build undo/atomic contracts on a phantom union unless reconciled.** Medium-high.
- **1-6 Df1 — in-flight gate has zero automated coverage**; `moved ⟺ plan.length>0` invariant unenforced. If engine ever reports `moved:true` with empty `transitionPlan`, `busyRef` stays true forever and all swipes drop. Silent deadlock risk. Medium.

**Medium**
- **1-6 Df2/Df3/Df4/Df5** — `tilesRef` second source of truth; orientation/resize mid-animation tile jump; unmount-clears-timer-without-releasing-gate (relevant once Epic 5/6 add overlays).
- **1-4 deferred** — `useState(() => newGame(rngRef.current))` mutates the RNG ref under StrictMode (double-init hazard). Masked today; Epic 2 snapshot/undo must settle init.
- **1-3 deferred** — AC-4 no-leak automated coverage stops at the planner; GameBoard reconcile/remove is manual-only.
- **1-7 deferred** — fit estimator ~10% optimistic for 6-digit Helvetica bold below the 44pt floor (numerals may clip sub-floor).
- **Faithful-port bugs preserved** (`pickIndex` NaN, 4×4 assumption, `spawnTile` mutation, noop full trace, `mergeValue` ignores 2nd operand) — intentional, but mines for any logic change in Epic 2.

**Low**
- Multiple completion-note/traceability count mismatches.
- 1-7 `BOARD_SIZE_FLOOR` exported but never referenced (AC correct by coincidence, no defensive test).
- 1-5 band-height formula duplicated between `App.tsx` and `Hud.tsx` (drift risk).
- 1-7 `tileInkFor` imported but unused; renderer still duplicates inline ink literal — divergence risk for Epic 9 theming.

### 1.6 Testing & Quality Insights

- Strong, deterministic coverage on pure logic (39→186 triade tests).
- **Benchmarking weaknesses:** 1-1 "worst case" computed the median (relabeled "tail p99"); under-measured ~1% of turns (noop moves skip spawn); 1-3 p99 gate flake risk under CI GC pressure.
- **Parity blind spots:** JSON round-trip normalizes NaN→null (masks divergences); 13/16 scenarios compare only TS==web, not an absolute oracle (shared-bug blind spot).
- **False-green guards:** purity/tripwire `try/catch` swallow and `PURITY_FILES` hand list both produced "green but not enforcing" — caught only by adversarial re-review.

### 1.7 Velocity / Complexity Signals

- 1-1 (spike): over-delivered CI, under-delivered physical gates (hardware). High review churn.
- 1-2: cheapest, highest value (verification).
- **1-3: most underestimated** — animation/render-state correctness was the real cost center (ghost tiles, noop-wipes-board, spring timing, impure updater, re-review).
- 1-4: decision-heavy, smooth feature, contract-heavy review.
- 1-5: code simple, blocked by manual validation (rotation un-automatable).
- **1-6: post-calibration rework** — design changed after dev pass (late device feedback).
- 1-7: smallest but still 4 review patches.
- **Pattern:** stories touching animation/render-state correctness (1-3, 1-6) needed adversarial re-reviews and produced most deferred debt. Epic 8 (feel suite) should expect the same.

## Part 2 — Next Epic Preparation (Epic 2: Adaptive Spawn)

### 2.1 What's Coming

Epic 2 ("Adaptive Spawn — O Jogo Cresce com o Jogador", FR6–FR10) is the **signature differentiator from Threes**: the 20% spawn pot for tiles `≥3` opens by board ceiling tier, with fixed 1/2 at 40/40 and a configurable halving-decay curve. It is the **first story set that actually changes spawn behavior** — highest-risk correctness extension of the port.

### 2.2 Dependencies on Epic 1 (concrete)

1. Engine core (`move`, `spawnTile`, `weightedValue`, `newGame`, RNG-injectable) exists — Epic 2 *extends* it to read `spawnConfig` + ceiling.
2. Pure-module + `PURE_MODULES` scan pattern — `spawnConfig`/`ceilingDetector`/`potResolver`/`weightedPicker` must be pure **and added to the scan** (the §1.3 escape pattern is the cautionary tale).
3. `mulberry32` + RNG injectability + `node --test` convention — keep determinism.
4. Trace already carries `spawned` — no render-layer change needed for bigger spawns.
5. **Snapshot/undo infra NOT yet built** — Epic 1 left only `matchScore.ts`. Epic 2 (2.1, 2.6) must introduce the immutable snapshot holding PRNG state + `pendingSpawn` (ADR-06). **This is the key structural gap Epic 1 leaves for Epic 2; Epic 3 undo and Epic 7 preview both depend on it.**
6. Contract mismatch (§1.5) to resolve before Epic 3 builds `undo(): ok | rejected` on a phantom union.
7. Faithful-port bugs must be re-checked when `weightedValue`/`spawnTile` are modified.

### 2.3 Critical Preparation (must complete before Epic 2 starts)

- **[ ] Reconcile the `ok | rejected` vs `moved: boolean` engine contract** — decide whether to keep `moved` or adopt the union. Owner: Architect + Dev. Blocks Epic 3 atomic undo.
- **[ ] Introduce the immutable snapshot model holding PRNG state + `pendingSpawn` (ADR-06) in 2.1/2.6**, not later. Owner: Dev.
- **[ ] Add Epic 2's pure spawn modules to `PURE_MODULES`/`PURITY_FILES`** so the tripwire actually scans them. Owner: Dev.
- **[ ] Close or formally accept device gate T5.2** (on-device p99) before any store-submission claim. Owner: Dev + QA.

### 2.4 Action Items

**Process Improvements**
1. Make the pure-module scan self-maintaining (derive from `src/engine` + `src/ui` globs instead of a hand list) so new pure files can't silently escape. Owner: Dev. Success: a new unlisted pure file fails CI.
2. Replace the completion-note test count with a CI-emitted count (or drop it) to kill the doc-drift class of review patches. Owner: Dev.
3. Budget explicit **review** effort per story, not just dev — Epic 1's pattern is "dev ships, review catches contract regressions." Owner: Project Lead.

**Technical Debt (priority)**
1. T5.2 on-device p99 gate — High — close before submission.
2. Engine contract reconciliation (`ok|rejected` vs `moved`) — Medium-High — before Epic 3.
3. 1-6 Df1 in-flight gate invariant — Medium — add a regression test for `moved ⟺ plan.length>0`.
4. 1-4 RNG-ref init under StrictMode — Medium — settle in Epic 2 snapshot work.

**Documentation**
1. Update architecture doc's stated engine contract to match the shipped `{board, score, moved, trace}` (or vice-versa). Owner: Tech Writer.

**Team Agreements**
- Keep RNG injectable; never introduce `Math.random` in engine/spawn code.
- New pure-layout/floor constants get a golden anchor test (1-5/1-7 lesson).
- Document every measured number with its method (benchmark-label lesson).

### 2.5 Significant-Discovery Check

- Epic 1 did **not** change the *direction* of Epic 2 — the plan is sound.
- But two findings must be handled *inside* Epic 2: (a) the snapshot/`pendingSpawn` model must be established now (it does not exist yet), and (b) the engine contract mismatch must be reconciled before Epic 3. These are prep items, not plan rewrites. **No epic-planning review session required** — but the snapshot decision is load-bearing for Epics 3, 6, 7.

### 2.6 Readiness Verdict

Epic 1 is feature-complete and test-covered on pure logic. **Not yet production-verified on device** (frame-rate gate open, landscape/gesture/numerals are manual-only). Recommended: close T5.2 + land the snapshot model in Epic 2 before claiming store readiness.
