# HUD & Input Review — Tríade (3-clone)

## Verdict

The spine pair is a strong contract for HUD *information hierarchy* (score always, preview always, best small, Clean bare — D-007 is airtight), for diegetic/non-diegetic separation, and for the E8 feel/performance split (declarative trace board + imperative worklets, Reduced Motion as sanctioned fallback). It is **not** yet an unambiguous contract for geometry and input: the landscape HUD (D-006) and the pause button (D-012) are described at the level of "thin edge layer / smaller numerals / chrome in the HUD edge" with no coordinates, and the input spec carries web-PWA vocabulary ("pointer capture") with no mapping to RN's responder/gesture system and no edge-case contract. E1 story-dev would inherit several build-it-invented decisions.

## Findings

- **[high] Landscape HUD layout is underspecified for build (S1.6, D-006).** *Location:* D-006 (.decision-log.md:51-54); DESIGN.md:223, 231, 263; EXPERIENCE.md:117, 154. "Thin edge layer with smaller numerals" specifies *that* things shrink, not *where they go*. Unstated: which edge hosts the layer (top/bottom/one long side), the element order (score/best/preview/pause), the preview card's landscape position ("landscape edge layer" DESIGN.md:263 is a placement class, not a position — the portrait "bottom corner near the swipe finger" rationale from D-007 is never translated to a landscape thumb), and the concrete reduced numeral size (score "drops a size step" DESIGN.md:223 — 34pt → what? no `typography` token exists). E1 would have to invent all of this for S1.4/S1.6. *Fix:* add a Landscape layout block to DESIGN.md with: edge choice, element order + offsets, preview card position, pause position, and new tokens (`typography.score-landscape`, `typography.caption-landscape`), each with a 16pt safe-margin note.

- **[high] Pause button placement is unspecified in both orientations (D-012).** *Location:* DESIGN.md:257 ("square glyph-only chrome in the HUD edge"), EXPERIENCE.md:37, 72. In portrait, score is center-top and the preview is bottom-corner, so "HUD edge" leaves a real choice (top-left vs top-right) — one of which may sit inside the board's swipe-capture zone once the board is maximized under the band. In landscape, the edge layer must hold score/best/preview *and* pause with no stated arrangement or collision-avoidance against the preview card. Pause is a hard accessibility/escape exit; E1 must not be free to place it. *Fix:* fix the corner (e.g., portrait top-right; landscape same side as the preview or opposite), state "outside the board swipe rect, ≥44×44, inside safe margins," and give the landscape layout block an explicit pause slot.

- **[high] Input contract uses web-PWA vocabulary ("pointer capture") with no RN mechanism and no edge-case spec (E1).** *Location:* EXPERIENCE.md:94, 123, 127; architecture game-architecture.md:177 ("RN touch/gesture system"); pinned version matrix architecture:138-160 (no react-native-gesture-handler, no PanResponder choice). RN 0.86 has no Pointer Events pointer-capture; the mechanism is either the responder system (`onStartShouldSetResponder`, `onResponderTerminationRequest`) or RNGH `Gesture.Pan()` with `activeOffsetX/Y`. The spine doesn't choose, and it doesn't specify behavior for the cases the web PWA already solved and the prompt names: system interruption / `pointercancel`, release off the board mid-gesture, and a second concurrent finger. The web PWA's solutions are not recorded anywhere (frozen surface, no parity mandate — EXPERIENCE.md:126), so E1 either reverse-engineers or invents. "No multi-touch requirements" (EXPERIENCE.md:127) is defensible as a *product* stance but is an implementation requirement in disguise: first-finger-wins, ignore touches 2..N, and no second `move()` while a swipe or its animation is in flight all go unsaid. *Fix:* pin the gesture mechanism (recommend RNGH Pan + its cancel/end semantics) in the version matrix; add a short Input Edge-Cases contract: cancel → no move; release off-board → resolve as captured; concurrent touch → ignored (first finger wins); swipe during in-flight animation → queued or rejected.

- **[medium] Safe-area mechanism is unspecified; the 16pt `{spacing.safe-margin}` is stated but the API is not.** *Location:* EXPERIENCE.md:155; DESIGN.md:227; architecture pinned matrix (architecture:138-160) omits `react-native-safe-area-context`. RN core `SafeAreaView` is deprecated and unreliable for landscape/asymmetric insets; the spine says "respect iOS safe areas" without naming `react-native-safe-area-context` (or any edge-inset source). Also unstated: the portrait preview card lives in the bottom corner (DESIGN.md:229) near the home-indicator / swipe-from-bottom gesture zone — functionally harmless (the card is non-interactive) but visually unconstrained; the landscape edge layer's relationship to the notch and home-indicator insets is likewise not specified. *Fix:* pin `react-native-safe-area-context` (Expo SDK 57 bundles it) and state that `{spacing.safe-margin}` is applied *on top of* per-edge insets in both orientations, including the preview card and pause button.

- **[medium] Fixed tile-numeral rule vs shrinking landscape tiles is unverified (E8).** *Location:* DESIGN.md:215-223 (fixed 32/13/9pt numerals "because they must stay legible inside the tile") vs DESIGN.md:231 / D-006 (landscape shrinks HUD numerals); S1.6 (epics.md:15). DESIGN.md:223 already distinguishes landscape-*HUD* smaller numerals from fixed *tile* numerals, so there is no direct contradiction — but the fixed sizes were chosen against the portrait tile size, and landscape tiles shrink (board maximized in the shorter dimension) with no min-tile-size or 9pt/13pt legibility check specified for E1/E8. The 9pt 6-digit tier (1536/3072+) is the risk point. The S1.1/device benchmark (architecture:183-204) measures frame budget, not legibility. *Fix:* state a min landscape tile size for the board-layout math, and add a one-line rule that the 13pt/9pt numerals are only used at tile widths that fit them (or that landscape re-runs the ink-contrast check).

- **[low] HUD information hierarchy is complete; Clean-board bareness is confirmed — no load-bearing gap.** *Location:* EXPERIENCE.md:115; DESIGN.md:274; D-007. No timer/combo/ceiling-bar is needed and rightly absent (no time pressure EXPERIENCE.md:109; ceiling tier is an invisible reward seen in the tiles EXPERIENCE.md:90; no combo mechanic exists). One nit: HUD "best" is not stated as lane-scoped — P3 and EXPERIENCE.md:183-184 imply per-lane bests, but nothing tells E1 the HUD readout must track the active lane's leaderboard; a merged/global best would leak score integrity (P3). *Fix:* one line — "best" on the HUD is the active lane's best.

- **[low] Diegetic/non-diegetic boundary is mostly clean; the preview card carries a mild conceptual blur.** *Location:* EXPERIENCE.md:113 (non-diegetic chrome) vs EXPERIENCE.md:144 ("next card in hand" diegetic framing) and DESIGN.md:263 ("oracle", a chip, not a tile). The classification is stated and the rendering spec is concrete, so E1 will build it correctly. The only residual ambiguity: DESIGN.md:241 says the HUD is flat and the player never sits inside it, but nothing explicitly excludes the preview card from the imperative feel layer — E8 could attach flash/particles to the preview card, which contradicts "feel effects never persist as UI" and the card's chrome role. *Fix:* one line in the feel section — feel-layer effects fire on the board only; the preview card is chrome and never animates with feel effects.

- **[low] Pause-during-animation freeze semantics are unstated.** *Location:* EXPERIENCE.md:81 ("Frozen board + scrim") vs swipe animations driven by Reanimated springs (architecture:268-273). Whether a pause tap mid-swipe waits for the animation to settle or cancels it is unspecified — a real but small E1/E8 ambiguity that affects the frozen-board snapshot under the scrim. *Fix:* one line — pause lets the in-flight animation complete, then freezes; the engine state under the scrim is the post-animation snapshot.
